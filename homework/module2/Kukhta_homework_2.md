# Домашня робота №2: аналіз портів і мережевих з’єднань

## Завдання 1. Аналіз відкритих портів

### 1.1. Команда

```bash
ss -tuln
```

### 1.2. Результат виконання

```text
Netid State  Recv-Q Send-Q Local Address:Port Peer Address:Port
udp   UNCONN 0      0      0.0.0.0:68         0.0.0.0:*
udp   UNCONN 0      0      127.0.0.53:53       0.0.0.0:*
tcp   LISTEN 0      128    0.0.0.0:22          0.0.0.0:*
tcp   LISTEN 0      4096   127.0.0.53:53       0.0.0.0:*
tcp   LISTEN 0      5      0.0.0.0:8080        0.0.0.0:*
tcp   LISTEN 0      128    [::]:22             [::]:*
```

### 1.3. Аналіз відкритих портів

| Протокол | Порт | Стан | Призначення |
|---|---:|---|---|
| UDP | 68 | `UNCONN` | DHCP-клієнт отримує мережеві параметри |
| UDP | 53 | `UNCONN` | локальна служба DNS |
| TCP | 22 | `LISTEN` | SSH — віддалений доступ до системи |
| TCP | 53 | `LISTEN` | локальна служба DNS |
| TCP | 8080 | `LISTEN` | локальний вебсервер Python |

Було знайдено більше трьох відкритих портів. Для TCP використовується стан `LISTEN`, тобто процес очікує на вхідні з’єднання. UDP не встановлює з’єднання, тому для нього команда `ss` показує стан `UNCONN`.

## Завдання 2. Аналіз процесів, що слухають порти

### 2.1. Команда

```bash
sudo ss -tulpn
```

Команду запущено через `sudo`, щоб побачити назви та PID системних процесів.

### 2.2. Результат виконання

```text
Netid State  Recv-Q Send-Q Local Address:Port Peer Address:Port Process
udp   UNCONN 0      0      0.0.0.0:68         0.0.0.0:* users:(("dhclient",pid=646,fd=6))
udp   UNCONN 0      0      127.0.0.53:53       0.0.0.0:* users:(("systemd-resolve",pid=705,fd=13))
tcp   LISTEN 0      128    0.0.0.0:22          0.0.0.0:* users:(("sshd",pid=812,fd=3))
tcp   LISTEN 0      5      0.0.0.0:8080        0.0.0.0:* users:(("python3",pid=2451,fd=3))
```

### 2.3. Визначені процеси

| Процес | PID | Порт | Протокол | Призначення |
|---|---:|---:|---|---|
| `sshd` | 812 | 22 | TCP | сервер віддаленого доступу SSH |
| `systemd-resolve` | 705 | 53 | UDP | локальне кешування та резолвінг DNS |
| `python3` | 2451 | 8080 | TCP | локальний HTTP-сервер |

Таким чином, кожен відкритий порт пов’язаний із конкретним процесом. PID є унікальним ідентифікатором запущеного процесу в системі.

## Завдання 3. Перевірка TCP-з’єднання

### 3.1. Команда

```bash
nc -vz google.com 80
```

У команді між доменом `google.com` і номером порту `80` обов’язково має бути пробіл.

### 3.2. Результат виконання

```text
Connection to google.com port 80 [tcp/http] succeeded!
```

### 3.3. Аналіз результату

| Параметр | Значення |
|---|---|
| Тип з’єднання | TCP |
| Порт | 80 |
| Служба | HTTP |
| Результат | з’єднання успішно встановлено |

TCP-з’єднання з `google.com` встановлюється успішно. Повідомлення `succeeded` означає, що віддалений сервер прийняв спробу встановлення TCP-з’єднання на порту 80.

## Завдання 4. Порівняння TCP та UDP

### 4.1. Перевірка UDP

Команда:

```bash
nc -u -vz -w 5 8.8.8.8 53
```

Результат:

```text
Connection to 8.8.8.8 port 53 [udp/domain] succeeded!
```

### 4.2. Перевірка TCP

Команда:

```bash
nc -vz -w 5 8.8.8.8 53
```

Результат:

```text
Connection to 8.8.8.8 port 53 [tcp/domain] succeeded!
```

### 4.3. Порівняння результатів

| Характеристика | TCP | UDP |
|---|---|---|
| Порт | 53 | 53 |
| Служба | DNS | DNS |
| Результат `nc` | `succeeded` | `succeeded` |
| Встановлення сесії | виконується TCP-handshake | сесія не встановлюється |
| Підтвердження доставки | є | немає гарантії |
| Контроль порядку пакетів | є | немає |

TCP спочатку встановлює з’єднання з віддаленим вузлом за допомогою handshake, тому успішний результат підтверджує доступність TCP-порту 53. UDP є протоколом без встановлення з’єднання. Повідомлення `succeeded` для UDP означає, що `nc` не отримав негайної помилки, але воно не є гарантією того, що UDP-пакет був доставлений або оброблений сервером.

## Завдання 5. DNS-резолвінг

